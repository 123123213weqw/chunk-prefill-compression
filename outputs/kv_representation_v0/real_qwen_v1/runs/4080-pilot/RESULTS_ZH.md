# 4080 真实 Qwen KV 表示压缩：实验结果

状态：已完成。4 条开发样本、2 个反事实样本对；正式测试集未使用。Qwen3-4B-Instruct-2507 / RTX 4080 / FP16。

## 结论

**带权聚类能构造更少的 KV 表示，比简单均值更好；但本轮结果不支持“无损”或“完美鲁棒”。**
这是每次只压缩一个 64-token chunk、其余 Full KV 保持原样的局部注意力重建，不是全缓存压缩或整模型生成评测。

## 主结果：FP16 原型 + FP32 log-weight

下列百分比是 attention 输出向量的相对误差，不是回答错误率。均值是 query/head 观测等权平均。

| 指标 | 64→32 | 64→16 |
|---|---:|---:|
| 混合上下文输出：平均误差 | 0.80% | 1.55% |
| 混合上下文输出：p95 | 3.36% | 6.75% |
| 混合上下文输出：p99 | 16.11% | 31.41% |
| chunk 内归一化输出：平均误差 | 16.29% | 31.14% |
| 近距离查询（1–64 token）：平均混合误差 | 3.94% | 7.60% |
| 近距离查询：p99 混合误差 | 48.64% | 76.72% |

### 为什么不能只看 0.80% / 1.55%？

被测试 chunk 的原始 attention mass 平均只有约 2.30%；问题末尾查询上更只有约 0.129%。大部分输出仍由未压缩 KV 贡献，因此局部信息损失会被混合上下文稀释。
近距离查询的原始 chunk mass 平均约 11.19%，相应误差明显更大；尾部 p99 达到约 48.64% / 76.72%。这正是不能用整体平均值宣称鲁棒的原因。

## 与均值基线比较

| 方法 | 64→32 平均混合误差 | 64→16 平均混合误差 |
|---|---:|---:|
| mean_no_mass | 1.93% | 2.55% |
| mean_mass | 1.35% | 1.86% |
| cluster_mass | 0.80% | 1.55% |
| cluster_mass_fp16 | 0.80% | 1.55% |

FP16 原型舍入未改变表中两位小数的结果；这不表示舍入误差严格为零。

## 字节与成本

- 每个 KV head、每个 chunk：原始 FP16 K/V 为 32,768 字节；64→32 后为 16,512 字节，约 1.984×；64→16 后为 8,256 字节，约 3.969×。已计 FP32 bias，未计容器/索引/allocator 元数据。
- 这是该 chunk 的表示张量字节比，不是整个 4K cache 或整卡显存压缩比。实际 forward 仍使用 Full cache；本轮没有部署 compact cache。
- FP32 原型在 64→32 时为 32,896 字节，反而略大于原始 FP16 K/V，因此必须区分条目数与字节数。
- CPU 参考聚类中位耗时：64→32 约 5.77 ms、64→16 约 3.06 ms，单位是一个 chunk / 一层 / 一个 KV head。不是优化 GPU 实现，不支持加速结论。

## 正确性与复现

- 5 项合成/因果遮罩自检通过。
- 160 个样本×层×KV-head 重建检查通过：FP32 reference 与实际 FP16 SDPA 输出的最大相对 RMS 约 0.02545%，低于预设 0.5% 门槛。该检查是分组 RMS，不是逐 query 最坏界。
- 全部输入 segment 的 tokenizer 长度和 token-id SHA256 经 runner 检查。
- 保存 261,120 行指标；这些行不是独立样本，不声称拥有同等数量的独立验证证据。
- 聚类只读当前 chunk 的 K；V 只用于组内均值。未来 Q 只用于评分，不训练、不调参。
- source/ 保存执行代码和开发数据，manifest.json 哈希已与本地副本核对。原始 Q/K/V .pt 保留在服务器，未下载到本机。
