# v6：反向局部压缩诊断

已完成 **36/36** 单元，RTX4080运行约4分36秒，原始生成token ID和Full identity gate重现，完整记录审计PASS。本实验使用已曝光的3个v5失败案例与3个正确对照，属于答案可见的事后机制诊断，不是新独立验证集。

## 核心操作

先前v5局部恢复实验：**几乎所有chunk都压缩，只有已知证据chunk不压缩**。本轮反过来：**几乎所有chunk都不压缩，只有已知证据chunk压缩到16**。每个条件都有“压缩同样数量非证据chunk”的等预算对照。仍是第30层、64-token chunk、FP16 SDPA、block1024的相同模型。

| 对原3道失败题做什么 | 正确数/3 |
|---|---:|
| Full，不压缩 | 3 |
| 所有T chunk都压缩到16 | 0 |
| **只压缩仓库证据所在1个chunk，其余全保留** | **3** |
| 只压缩同数量非证据chunk，其余全保留 | 3 |
| **只压缩仓库+箱数证据所在2个chunk，其余全保留** | **3** |
| 只压缩同数量非证据chunk，其余全保留 | 3 |

三个正确对照在所有条件下均正确。与之前的反向实验并读：在“其他chunk都压缩”的背景下，只保留仓库证据chunk可救回2/3；但在“其他chunk都不压”的背景下，只压该证据chunk也不会让它们答错。因此，错误**不是某个答案chunk单独被压缩的必然结果**；多处压缩的组合/全局影响更符合已观察结果。此前一个失败案例连完全保护两处原始证据仍未恢复，也支持不能只看原文答案位置。

这不是证明“分布式信息丢失”作为唯一机制：压缩数量改变时，键值表示、attention归一化、RoPE位置采样与浮点数值也一起改变。本次没有把它们单独隔离。也没有证据表明仅需保持几个证据chunk就能得到通用可靠算法——这些chunk是**已知答案后才定位**的。
